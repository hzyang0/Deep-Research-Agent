# 设计文档（Design Doc）

本文记录 Deep Research Agent 的核心设计决策与权衡。每一节都对应面试时可能被追问的点——读懂这里，你就能从"会用框架"升级到"理解 Agent 工程"。

## 1. 为什么选"规划-执行-反思"而非纯 ReAct？

**ReAct（Reason+Act 单循环）**：模型在一个循环里交替"思考-行动-观察"，没有预先规划。简单、灵活，适合短任务。

**它在研究任务上的问题**：开放式研究的轨迹很长（要搜十几次、读十几个网页）。ReAct 的单一长轨迹里，模型容易在中途迷失方向、重复搜索、或过早收尾。上下文越堆越长，"迷失在中间"（lost in the middle）问题越严重。

**本项目的选择**：先用规划器把问题拆成相对独立的子问题，再逐个执行，最后做全局反思。好处：
- 每个子问题的上下文是隔离的、聚焦的，模型不易跑偏。
- 子问题天然可并行（当前实现是串行，但架构上支持并行优化）。
- "规划 + 两层反思"让 Agent 既有方向感，又能动态纠偏。

**代价**：规划器若拆得不好，会从源头限制覆盖面。所以规划器用 SMART 档 + 低温，并要求拆出"可被搜索回答的具体子问题"。

## 2. 为什么用结构化 state，而不是堆叠对话历史？

入门写法常把所有中间结果拼进一个不断膨胀的 prompt。问题三连：上下文爆炸（贵、触顶）、模型被无关内容干扰、难调试。

本项目用一个 `ResearchState` 对象作为单一事实来源，每个步骤只读它需要的字段。收益：
- 上下文精确可控，token 不失控。
- state 可序列化、可打印，调试和可观测性强。
- `search_count` 这类计数器天然支撑防死循环。

这是"会写 prompt"到"会做 Agent 工程"的认知分水岭。

## 3. 终止条件与防死循环

Agent 最危险的失败模式是无限循环烧钱。本项目设了三层终止保障：

1. **反思器的软终止**：每搜一轮后，反思器判断"信息是否充分"，充分则提前结束该子问题。
2. **单子问题搜索次数硬上限**（`max_searches_per_subq`）：即使反思器一直说"不够"，也不会超过这个次数。这是**兜底**，不依赖模型判断。
3. **全局补充子问题数量上限**：全局反思最多补 2 个，且补充的子问题同样受第 2 条约束。

结论：流程**一定会终止**，且总搜索/调用次数有明确上界 → 成本可预估。`tests/test_agent.py::test_dead_loop_guard` 专门验证了第 2 条。

## 4. 成本优化：模型分级 + 定向摘要

这是项目里最能体现工程成熟度的设计。

**模型分级**：把 LLM 调用分成两档。
- FAST 档（便宜小模型）：网页定向摘要——高频、低难度（读一段、抽要点）。
- SMART 档（强模型）：规划、反思、报告写作——低频、高难度。

**定向摘要（query-focused summarization）**：不把网页全文喂给报告模型，而是先用小模型针对当前子问题把每篇网页压缩成 ~150 字相关摘要。

**算一笔账**：一次研究抓 ~15 个网页，每篇正文 ~3000 token。
- 朴素：15×3000 = 45000 token 全喂给贵模型。
- 本方案：每篇用便宜模型压到 ~300 token，贵模型只读 15×300 = 4500 token，且这 4500 走的还是贵模型，前面的压缩走便宜模型。
综合下来贵模型的输入量降一个数量级，整体成本显著下降。

## 5. 防幻觉 / 可溯源引用

LLM 最大的风险是一本正经地编造事实和来源。本项目的对策是**让引用绑定到真实抓取的数据**：

1. 报告生成时，给每条 finding 编号 `[1] [2] ...`，并各自附带它真实的 `source_url`。
2. 提示词强约束：每个论断必须基于所提供的发现，句末标 `[编号]`，禁止编造发现里没有的事实。
3. 报告末尾的"参考来源"列表由程序自动拼接，序号一一对应真实 URL——不经过模型，杜绝编造链接。

`evaluate_citation_accuracy` 用纯程序校验报告里的 `[n]` 是否越界，零成本地量化"模型有没有编引用"。

## 6. 工具层的可插拔设计

搜索和抓取都封装成独立工具，对外暴露稳定接口（`search(query) -> [SearchResult]`、`run(...) -> Finding | None`）。Agent 业务层不关心底层实现。

意义：默认用免费的 DuckDuckGo 保证零门槛；生产环境换成 Tavily/SerpAPI 只需实现同一接口，业务代码一行不改。这就是"工具层应可插拔"的体现。

## 7. 鲁棒性：到处都在"优雅降级"

外部依赖（搜索、抓取、模型）都会失败。本项目的原则是**失败不崩溃，而是降级**：
- LLM 调用：失败重试，重试耗尽才抛。
- 搜索：失败重试，最终返回空列表（不抛），让 Agent 把该子问题视为信息不足。
- 抓取/摘要：单个网页失败返回 None，自动跳过，不影响其它来源。

`test_graceful_degradation_on_empty_search` 验证了"搜索全空时仍能产出报告"。

## 8. 可观测性

`ResearchState.trace` 记录全过程，`LLMUsage` 累计 token 与调用次数。运行结束打印成本数字。这让"它到底做了什么、花了多少钱"完全透明——既利于调试，也是面试演示的有力素材。
